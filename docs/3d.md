# 3D assembly viewer

[Open the 3D tab](https://ivere27.github.io/ulva/#3d) to rotate, zoom and pan the
board assembly. The shared viewer also has Routing, Schematic and Orders tabs.
Show or hide components by reference and toggle mounted modules.
These controls change the displayed assembly only; they do not modify the BOM,
footprints or KiCad board.

Drag to orbit, scroll or pinch to zoom, and right-drag or use two fingers to pan.
Use the view buttons for top, bottom and isometric views. The Parts panel supports
search, individual visibility and carrier/module groups.

The board geometry and component positions come from
[`ulva_controller.kicad_pcb`](../ulva_controller.kicad_pcb). Some component bodies
use simplified models. Mounted modules and their heights are illustrative, so
the viewer is not a mechanical fit or clearance qualification.

## Local viewing

Keep the complete `docs/` directory, including the JavaScript bundles, and open
[`docs/index.html`](index.html) directly in a browser. No server or internet
connection is required. Routing and 3D need explicit access to their data files
when the page is opened with `file://`, so select them when prompted:

- **Routing:** `docs/routing/board.svg`.
- **3D:** `docs/3d/assembly.json` and `docs/3d/board.glb` together, from the same
  export.
- **Schematic:** images and PDF load directly; no file selection is needed.
- **Orders:** the selector includes its data and opens directly; see the
  [order workflow](../tools/README.md).

On GitHub Pages, the data files load automatically. You can also use an optional
local server for automatic loading:

```sh
python3 -m http.server 8000 --directory docs
```

Open [localhost:8000/#3d](http://localhost:8000/#3d). The standalone
[3D page](https://ivere27.github.io/ulva/3d/) and
[routing page](https://ivere27.github.io/ulva/routing/) remain available.

## Export

Run from the repository root with Python 3.10 or later, KiCad 9's `pcbnew` Python
module and `kicad-cli` available in that environment, and Node.js 22 or later.
Model export uses the bundled Three.js code. If standard KiCad models are
missing, download them into the local build cache:

```sh
python3 scripts/export_3d.py --download-models
```

The default output is `build/3d/`, including `board.glb` and `assembly.json`.
The GLB contains the scene; the JSON records component metadata and model
assumptions. Installed or cached models can be reused without `--download-models`.
Review the export before updating the viewer assets:

```sh
python3 scripts/export_3d.py --update-docs
python3 scripts/export_viewer_info.py
```

To download models and update the viewer in one step, use
`python3 scripts/export_3d.py --download-models --update-docs`.

The 3D exporter updates `docs/3d/board.glb` and `docs/3d/assembly.json` after
checking that the source still matches the export. The metadata command refreshes
the shared viewer's Version details from existing files. It preserves the 3D
export's recorded source hash; it does not regenerate an older model.

These commands do not commit, push or deploy files. With GitHub Pages configured
to serve the publishing branch's `/docs` directory, the shared viewer is served
at `/ulva/` after publication. See
[GitHub's publishing-source instructions](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

## Rebuild the viewer

After editing the 3D viewer JavaScript, rebuild its browser bundle:

```sh
python3 scripts/build_3d_viewer.py
python3 scripts/build_3d_viewer.py --check
python3 scripts/export_viewer_info.py
```

This uses Node.js and npm with esbuild pinned to 0.25.10. The first build downloads
the package; use `--offline` to rebuild from the npm cache. These build tools are
not needed to open the viewer, and rebuilding the bundle does not export the PCB.

## Formats

| Format | Use |
| --- | --- |
| `.kicad_pcb` | Authoritative editable board, footprints and model assignments |
| `.glb` | Binary glTF scene for the browser viewer and compatible 3D tools |
| `.wrl` | VRML scene or component model used by KiCad's visual export |
| `.step` / `.stp` | Solid geometry for exchange with mechanical CAD tools |

KiCad 9 also provides native `pcb export glb`, `pcb export vrml` and
`pcb export step` commands. A native export uses the models assigned in the
board; it does not automatically add this viewer's illustrative modules or
component controls. See the [KiCad CLI reference](https://docs.kicad.org/9.0/en/cli/cli.html).

STEP export requires solid component models. KiCad's `--subst-models` option can
use a matching STEP file in place of a WRL model; WRL-only shapes are omitted.
See the [KiCad 3D export documentation](https://docs.kicad.org/9.0/en/pcbnew/pcbnew.html).
